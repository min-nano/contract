# ADR 0005: 電子署名の要否と、電磁的交付の技術的担保をどう置くか

- ステータス: **提案（決定していない。顧問弁護士のレビュー待ち）**
- 日付: 2026-08-14
- 関連: [01-legal-requirements.md §4](../01-legal-requirements.md),
  [04-external-services.md §1](../04-external-services.md),
  [adr/0002](0002-esign-provider-abstraction.md), [adr/0004](0004-delegate-retention-to-moneyforward.md)

## 背景

当初、電子契約サービス（マネーフォワード クラウド契約）の利用を前提に設計してきた。
その前提には「電磁的方法で契約書面を交付するには電子署名が要る」という**暗黙の想定**があった。

この想定を条文で検証したところ、**建築士法は電子署名を要求していない**ことが分かった
（→ [01-legal-requirements.md §4.2.1](../01-legal-requirements.md)）。

あわせて、現在の契約（マネーフォワード クラウドのパーソナルプラン）では
**クラウド契約 API v2 の全エンドポイントが 403** であり、参照系も書き込み系も利用できない
（→ [04-external-services.md §1.3](../04-external-services.md)）。
API を使うにはプランかオプションの追加が必要で、費用は未確認。
他社サービスへ移す場合は年10万円超の追加コストが発生する。

**「電子署名は本当に必要か」を先に決めないと、電子契約サービスの選定もコストも決められない。**
順序が逆になっていた。

## 論点

### 法令が要求していること（規則17条の39第2項）

1. 相手方がファイルへの記録を出力することにより**書面を作成できる**こと
2. 記録された事項について**改変が行われていないかどうかを確認することができる措置**
3. 閲覧に供する方法を採る場合、**記録した旨を通知**すること

加えて令8条（令7条準用）により**相手方の承諾**が必要。
規則17条の40（示すべき種類・内容）、規則17条の41（承諾の取得方法）が手続を定める。

**「電子署名」の語は建築士法・施行令・施行規則に一度も現れない**（e-Gov 全文検索で0件）。

### 他法令との比較

| 法令 | 改変への措置 | 本人確認・署名者の明示 |
| --- | --- | --- |
| **建築士法** 規則17条の39 | 改変が行われていないかどうかを**確認**できる措置 | **規定なし** |
| 宅地建物取引業法 規則16条の4の8 等 | 確認できる措置 | **宅地建物取引士が明示されるものであること** |
| 建設業法 規則13条の4 | 確認できる措置 | **相手方が本人であることを確認することができる措置** |

必要な場面では明文で置かれている。建築士法にはない。

### 電子署名法との対応

同法2条1項の「電子署名」の定義は2要件（①作成者への帰属を示す ②改変の確認ができる）。
**規則17条の39第2項2号が要求するのは②だけ**であり、①は要求されていない。

一方、同法3条の真正成立の推定は「**本人だけが行うことができる**電子署名」が
行われている場合に働く。電子署名がなければこの推定は働かず、
紛争時に成立の真正を**自ら立証**する必要がある。

→ **法令遵守（監督処分の回避）と、紛争時の立証は別の問題である。**

## 選択肢

| 案 | 内容 | 法令適合 | 証拠力 | コスト |
| --- | --- | --- | --- | --- |
| **A** | 自前で完結。ハッシュ値（SHA-256）の記録・通知、追記専用の監査証跡、承諾記録 | 条文上は満たしうる | **最弱**。推定効なし | ゼロ |
| **B** | A ＋ **タイムスタンプ**（時刻認証局） | 満たす。重説書面の「改変を防止」にも寄与 | 中（存在証明・非改ざん証明） | 低 |
| **C** | 電子契約サービスを利用（現行路線） | 満たす | **最強**（推定効＋長期署名10年） | MF: 要問い合わせ／他社: 年10万円超＋送信料 |

いずれの案でも、**令8条の承諾取得・規則17条の40/41 の手続・出力可能性・通知**は
本システム側で実装する必要がある。ここは案によらず共通。

## 推奨（決定ではない）

**案B を推す。**

- 案A は、消費者（建築主）を相手にする契約で真正成立の推定を完全に捨てることになる。
  設計・工事監理の委託は金額が大きく履行期間も長いため、紛争時の立証負担は現実的なリスク。
  コスト差（タイムスタンプは低廉）に見合わない
- 案C は証拠力が最も高いが、**現在 API が使えず**、使えるようにする費用も不明。
  他社へ移す場合の追加コストは事務所の規模に対して重い
- **電子帳簿保存法の真実性の要件**（タイムスタンプ、または訂正削除の記録が残るシステム）にも
  タイムスタンプは効く。案Bはここで二重に価値がある
- **重説書面は「改変を防止するための措置」**が要求されており（規則22条の2の3第2項2号）、
  ハッシュ記録だけでは足りない可能性が高い。案Bはこれに応えられる

ただし **これは条文の読み方の整理であって法的判断ではない。** 下記の条件が揃うまで決定しない。

## 決定の前提条件（Phase 0-3 で確認する）

1. **国土交通省の技術的助言・解釈通知の有無。**
   建設業法には施行規則の技術的基準に関するガイドラインがあり、電子署名が具体的手段として
   示されている。建築士法に同種の文書があれば、条文の文言以上の解釈が示されている可能性がある
2. **改正法に伴う政省令改正の内容。** 規則17条の39 は面積要件を含む見出しのままであり、
   改正が入る。その際に技術基準が変わる可能性がある
3. **顧問弁護士の見解。** とくに次の2点
   - 「署名又は記名押印」の要件が電磁的方法において不要と読めるか
   - 消費者契約において推定効を持たない電磁的交付を採ることの実務上のリスク
4. **MF からの回答**（API の利用条件と費用）。案C を維持できるかの判断材料

## この ADR が他に与える影響

- **[adr/0002](0002-esign-provider-abstraction.md)（プロバイダ抽象化）**: 案A・案Bを採る場合、
  `EsignProvider` に**自前実装**という第4の実装が加わる。抽象化してあるため上位フローは変わらない。
  **抽象化の判断がここで報われる形になる**
- **[adr/0004](0004-delegate-retention-to-moneyforward.md)（永続保管の委譲）**: 案A・案Bでは
  MFに預ける対象が存在しなくなるため、**保管は自前に戻る**。adr/0004 は前提ごと組み替えになる
- **[04-external-services.md](../04-external-services.md) §1.3 の403問題**: 案A・案Bなら**消滅する**
- **[ROADMAP.md](../ROADMAP.md)**: Phase 0-1（API の 403 解消）の優先度が下がり、
  Phase 0-3（法務レビュー）が最優先になる

## 結果と再検討の条件

- 案A・案Bを採る場合、**規則17条の39第2項の3基準を満たすことを、実装とテストで明示的に担保する**こと。
  「たぶん満たしている」では監督処分（法26条2項1号）のリスクを負う。
  基準ごとに対応するテストを書き、根拠条文をコメントに残す
- 相手方が電子署名を求めた場合、または相手方の社内規程で電子契約サービスの利用が
  指定された場合に備え、案Cへ切り替えられる状態（`EsignProvider` の実装差し替え）を維持する
- 施行期日政令および政省令改正が公布された時点で、本 ADR を再検証する
