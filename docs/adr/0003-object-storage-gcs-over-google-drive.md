# ADR 0003: アプリケーションのストレージに Google Drive ではなく Cloud Storage を使う

- ステータス: 採用
- 日付: 2026-08-13
- 関連: [03-architecture.md §4](../03-architecture.md)

## 背景

Google Workspace を契約済みであり、バックエンドのストレージとして Google Drive を
利用できる状態にある。追加コストがかからず、既に図面のやりとりに使っている。

本システムが扱うのは、受領図面、建築主の個人情報を含む契約書、締結済PDF、
合意締結証明書である。これらは外部に漏れた場合の影響が大きく、
かつ電子帳簿保存法に基づく長期保存の対象になる。

## 決定

**アプリケーションのデータストアには Cloud Storage を使う。Google Drive は使わない。**

Drive は「人が図面をやりとり・共同編集する作業場所」として従来どおり残す。
Drive 上の受領フォルダから本システムへ取り込む導線を設け、
**取り込み時点で Cloud Storage にコピーし SHA-256 を固定**する。
以後、契約に添付されるのは Cloud Storage 上の不変オブジェクトのみとする。

## 理由

Workspace のセキュリティが不足しているわけではない。問題は**運用上の事故確率**と、
**アプリケーションのストレージとしての設計適合性**である。

| 観点 | Google Drive | Cloud Storage |
| --- | --- | --- |
| 誤公開のリスク | 「リンクを知っている全員」に**UIから1クリックで**変更できる。契約書・図面では致命的 | 均一なバケットレベルアクセスと公開アクセス防止を**組織ポリシーで強制**でき、意図しない公開が構造的に起きない |
| アカウントを持たない相手への一時公開 | 権限付与はアカウント単位。発注者向けの安全な一時公開が苦手 | **署名付きURL**（有効期限つき）で直接渡せる。本システムの中心的な要件と合致する |
| 監査ログ | Workspace 監査ログ。アプリ操作との突合が弱い | Cloud Audit Logs でアプリ・IAMと同一基盤で追跡できる |
| 暗号鍵 | 顧客管理鍵の適用範囲が限定的 | **CMEK**（Cloud KMS）をバケット単位で適用できる |
| 改ざん・削除防止 | ゴミ箱からの復元、オーナー変更などのゆらぎがある | **バケットロック（保持ポリシー）＋バージョニング**で、電子帳簿保存法の保存要件に対応しやすい |
| サービスアカウント運用 | 共有ドライブでないとサービスアカウント所有ファイルの扱いが煩雑。個人アカウントに紐づくと**退職・異動で権限を失う** | IAM で完結。人の異動と無関係 |
| APIの性格 | 同期・コラボレーション向け。クォータとレート制限がアプリ用途に不向き | オブジェクトストレージとして設計されている |

決め手は上位2行。**「共有設定を1クリック間違えると外部公開される」という経路を、
アーキテクチャから消せること**の価値が高い。
建築主の氏名・住所・建物所在地・図面という組み合わせは、漏洩時の影響が大きい。

また、Drive でなければ実現できない要件は現時点で存在しない。
**Workspace を契約済みであることは、Drive をアプリのストレージにする理由にはならない。**

## 検討したが採らなかった案

### 共有ドライブ＋サービスアカウントで Drive をデータストアにする

サービスアカウント所有の問題は共有ドライブで緩和できるが、
誤公開リスク、署名付きURL相当の機能の不在、保持ポリシーの弱さは解決しない。

### Drive と Cloud Storage の二重管理（両方に正を置く）

同期のずれが必ず起きる。「どちらが正なのか」が曖昧なまま契約書を扱うことになる。
**正は Cloud Storage の1箇所**とし、Drive は取り込み前の作業場所に限定する。

### 締結済PDFのみ Cloud Storage、受領図面は Drive

契約書に添付する図面こそ同一性の担保が必要（[02-business-flow.md §2.0](../02-business-flow.md)）。
添付対象が可変のストレージにあると、「契約時の条件が曖昧にならないように」という
本システムの目的そのものが崩れる。

## 結果

- バケットは用途別に3つ（`-received` / `-generated` / `-executed`）。
  すべて uniform bucket-level access、公開アクセス防止、CMEK。
  `-executed` はバケットロックによる保持ポリシー10年。
- 発注者へのファイル配布は署名付きURL（有効期限15分）。
- Drive からの取り込みは Drive Picker またはアップロードで行い、取り込み時に SHA-256 を固定する。

## 再検討の条件

Drive に、バケットロック相当の保持ポリシーとアカウント不要の期限付き署名URL相当の機能が
提供された場合、統合による運用簡素化を再検討する余地がある。
