# 業務フローと画面

**業務のうち、システムが担うのは書類を作るところだけである**
（→ [adr/0007](adr/0007-document-preparation-only.md)）。
本書は**全体の流れの中でツールがどこに立つか**と、**画面の設計**を扱う。
承諾・交付・説明・保存の手順そのものは [07-operations.md](07-operations.md) にある。

---

## 1. 全体の流れ

```
                          ┌──────────────────────────────┐
                          │  contract-formatter（本ツール） │
                          └──────────────────────────────┘

 図面等の資料を受領・見積依頼
        │
        ├─ ① 電磁的方法による交付の承諾を求める ────────────── 運用（定型文 A）
        │
        ├─ ② 報酬を算定する ─────────────────────── ★ツール（報酬算定）
        │     業務報酬内訳書PDFを作る ────────────────── ★ツール
        │     見積書はMFクラウド請求書の画面で作る ────────── 運用
        │     見積書＋内訳書を送る ───────────────────── 運用
        │
        ├─ ③ 重要事項説明書を作る ─────────────────── ★ツール
        │     ※ 相手方が建築主の場合のみ（法24条の7）
        │     事前に交付する ───────────────────────── 運用（定型文 B）
        │
        ├─ ④ 重要事項の説明を行う（対面／ビデオ通話・免許証提示） ── 運用
        │     実施記録の欄を埋め、建築主の署名をもらう ────────── 運用
        │
        ├─ ⑤ 契約書を作る ────────────────────────── ★ツール
        │     双方の氏名を印字してPDFを交付する ─────────── 運用（定型文 C）
        │     相手方から同意と提供の返信をもらう ────────── 運用（定型文 D）
        │
        ├─ ⑥ 契約書PDFと往復メールを保存する ─────────────── 運用
        │
        └─ ⑦ 設計変更が生じたら、原契約PDFを開いて
              変更契約書を作る ───────────────────── ★ツール
```

**★が5か所。それ以外はメールとチェックリストで回す。**

> **順序を入れ替えてはならないところが2つある。**
> ① **承諾は電磁的方法での交付より前**（令8条。承諾なく送ると交付したとみなされない）
> ② **重要事項説明は契約の締結より前**（法24条の7「あらかじめ」）
> システムはこの順序を強制しない（強制できる状態を持たない）ため、
> **チェックリストで守る**（→ [07-operations.md §5](07-operations.md)）。

## 2. 画面

**portal の他のPDFツールと同じ考え方**（新規作成／開く／保存／別名で保存）。
利用者が「別のアプリを覚える」ことにならないようにする。

```
┌────────────────────────────────────────────────┐
│ 設計等業務委託契約書 作成ツール          [雛形を設定]  │
├────────────────────────────────────────────────┤
│ 編集中: 20270415_山田太郎_3300000.pdf   [新規] [開く] │
├────────────────────────────────────────────────┤
│  ▼ 0. 契約の種類と相手方                              │
│      契約種別／建築士が行う業務か／相手方は建築主か       │
│      → ここで「何が必要か」が決まる（§3）              │
│  ▼ 1. 当事者                                        │
│      建築士事務所／開設者／相手方                       │
│  ▼ 2. 建築物の概要                                   │

│      設計図書の種類／照合と報告の方法／種類・内容・方法／期間│
│  ▼ 4. 従事する建築士・建築設備士・再委託                 │
│  ▼ 5. 報酬                        ┌──────────────┐ │
│      告示による算定／補正／支払の時期│ 法定記載事項     │ │
│  ▼ 6. 解除・特約                  │  法1項1号 ✓     │ │
│                                   │  法1項3号 ✓     │ │
│                                   │  規則7号 未入力  │ │
│                                   ├──────────────┤ │
│                                   │ 報酬（税込）     │ │
│                                   │  3,323,100 円   │ │
│                                   └──────────────┘ │
├────────────────────────────────────────────────┤
│ [契約書を作る] [重要事項説明書を作る] [業務報酬内訳書を作る] │
```

### 決めごと

| # | 決めごと | 理由 |
| --- | --- | --- |
| 1 | **法定記載事項チェック表を右に貼り付ける**（1080px 以上で2列。portal の `.has-dock`） | 「何を漏らしていないか」が常に見えている状態が、このツールの価値そのもの（→ [05-documents.md §7](05-documents.md)） |
| 2 | **報酬の額を入力のたびに出す** | 面積や業務範囲を動かしながら金額を見られる（→ [06-fee-estimation.md](06-fee-estimation.md)） |
| 3 | **1つの入力から契約書・重説書面・内訳書の3つを作る** | 同じ事項を3回入力させない。**必須検証だけは書類ごとに分ける**（→ [05-documents.md §1](05-documents.md)） |
| 4 | **入力漏れのある節は自動で開く** | portal の `<portal-section>` の既存の挙動 |
| 5 | **メールの定型文をコピーボタンで出す** | 案件の情報を差し込んだ状態で出す。手で書き起こさせない（→ [07-operations.md §2](07-operations.md)） |
| 6 | **保存先は「編集中のファイル」か、そのつど選ぶフォルダ** | 共有設定として固定しない（portal の証明書ツールと同じ） |
| 7 | **既定のファイル名は `YYYYMMDD_取引先名_金額.pdf`** | 電帳法の検索要件への備え（→ [07-operations.md §4.2](07-operations.md)） |

### ファイル操作

| 操作 | 内容 |
| --- | --- |
| **新規作成** | 空のフォーム。事務所・建築士の情報は共有設定から初期値を入れる |
| **開く** | 作成済みPDFを Drive から選ぶ、または手元からアップロードする。入力が復元される |
| **保存**（上書き） | 編集中のファイルの内容を差し替える。名前も場所も変わらない（Drive の版履歴が残る） |
| **別名で保存** | ファイル名と保存先フォルダを指定する |
| **未保存のまま移ろうとしたとき** | 保存するかどうかを尋ねる |

## 3. 「何が必要か」の判定

**節0の入力から、3つの義務の適用を判定する**（→ [05-documents.md §4](05-documents.md)）。
**3つは適用条件が違う。同じフラグで扱わない。**

| 入力 | 書面の相互交付 | 重要事項説明 | 見積書 |
| --- | --- | --- | --- |
| 設計受託・相手方＝建築主 | **必要** | **必要** | 推奨 |
| 設計受託・相手方＝元請け設計事務所 | **必要** | **不要** | 推奨 |
| 工事監理受託・相手方＝建築主 | **必要** | **必要** | 推奨 |
| 耐震診断 | 不要 | 不要 | 推奨（告示第670号） |
| 調査・検査、手続の代理 | 不要 | 不要 | 推奨（告示なし） |

**画面の反応**

- **必要** → 法定記載事項を必須検証する。**欠けていればPDFを作らせない**
- **不要**（重説） → 重説のタブを出さない。**「作れ」と促さない**（義務がないため）
- **推奨**（見積） → 警告のみ。**止めない**（努力義務。監督処分の対象外）

> **重説の要否は契約種別だけでは決まらない。**
> 法24条の7第1項は「設計受託契約又は工事監理受託契約を**建築主と**締結しようとするとき」と
> 定めており、元請け設計事務所からの受託には適用がない
> （→ [01-legal-requirements.md §3.0](01-legal-requirements.md)）。
> **義務のない相手に重説を強制すると、実務を止めるだけになる。**

## 4. 変更契約

**原契約のPDFを開いて作る**（→ [05-documents.md §5](05-documents.md)）。

```
[開く] → 原契約PDF → 入力が復元される
                    → 変更する項目だけを直す
                    → [変更契約書を作る]
                    → 変更前／変更後の対照表が自動で作られる
```

- **差分が空なら作らせない**（変更のない変更契約書は書面として意味がない）
- 原契約のPDFは上書きしない。変更契約書は別ファイルとして保存する
- 変更契約書にも変更後の完全な入力が埋まるので、次の変更はそこから作れる
- **承諾は原契約のときのものを流用**できる（撤回されていない限り）。
  重説は原契約時に実施済みであれば再実施は要らない

## 5. 状態を持たない

**このツールに「契約のステータス」は無い。**

現行設計は `DRAFT → QUOTE_SENT → CONSENT_GIVEN → … → EXECUTED` という
状態遷移をサーバ側で管理していたが、**交付も承諾も受領もシステムの外に出た以上、
遷移を検知する手段が無い**（→ [adr/0007](adr/0007-document-preparation-only.md)）。
**知らない状態を持つと、必ず実態とずれる。**

代わりに:

| 知りたいこと | どこを見るか |
| --- | --- |
| 承諾を得たか | メールボックス（定型文 A の返信） |
| 交付したか | 送信済みメール |
| 相手方の同意を得たか | メールボックス（定型文 D の返信） |
| どこまで進んだか | **チェックリスト**（→ [07-operations.md §5](07-operations.md)） |
| 契約書はどこにあるか | Drive の契約書類フォルダ |

**件数や期限を一覧したくなったら、そのとき台帳を足す**（→ [ROADMAP.md](ROADMAP.md)）。
先に作らない。
