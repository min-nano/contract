# 報酬の算定（見積ロジック）

**目的は「実務を楽にすること」である。** 案件ごとに考え直すのをやめ、
**同じ入力からは必ず同じ金額が出る**状態を作る。
副産物として、法24条の10（報酬の算定の根拠を明らかにするための見積書。**努力義務**）に
そのまま対応できる。

> **法24条の10は努力義務であり、監督処分の対象ではない**
> （→ [01-legal-requirements.md §1.5](01-legal-requirements.md)）。
> **見積を作っていなくても契約書は作れる。** 画面は警告を出すだけで、止めない。

---

## 1. 何を固定し、何を可変にするか

**告示の略算法を土台にし、事務所ごとの単価と係数で補正する。**
土台と補正を混ぜず、**内訳書には両方を出す。**

| 層 | 内容 | 出どころ | 変わる頻度 |
| --- | --- | --- | --- |
| **① 告示の略算法** | 標準業務人・時間数の別表、費目の構成、業務区分の細分 | **告示の原文**（コードに定数として持つ） | 告示の改正時のみ |
| **② 事務所の設定値** | 人件費単価、経費率、技術料等経費率、最低報酬額 | **Firestore の共有設定**（画面から編集） | 年1回程度 |
| **③ 案件ごとの入力** | 建築物の類型、延べ面積、受託する業務の範囲、特別経費 | フォーム | 案件ごと |

> **①をコードに、②を設定に置く理由。** 告示の別表は**法令の写し**であり、
> 誤って編集されては困る。改正時にはテストごと差し替える。
> 一方、人件費単価は事務所の実態であり、**画面から直せなければ使われなくなる。**

---

## 2. 適用する告示は2本ある

**費目の構成が違うため、1つの計算器に押し込めない**（→ [01-legal-requirements.md §1.7](01-legal-requirements.md)）。

| 告示 | 対象 | 費目の特徴 |
| --- | --- | --- |
| **令和6年国土交通省告示第8号** | 一般（設計、工事監理、建築工事契約に関する事務、建築工事の指導監督） | 標準的な構成 |
| **平成27年国土交通省告示第670号** | **耐震診断・耐震改修**に係る業務 | **検査費**（超音波探傷検査、コンクリート供試体の圧縮強度検査などの第三者委託費用）を持つ。標準業務人・時間数の別表も別 |

契約種別から自動で選ぶ。

```
seismic_diagnosis          → 告示第670号
seismic_retrofit_design    → 告示第670号
design / supervision       → 告示第8号
inspection / procedure_agency / other → 告示なし（実費積上げ）
```

> **告示第98号（平成31年）は廃止されている。** 告示第8号 附則第2項で確認済み
> （→ [01-legal-requirements.md §1.7](01-legal-requirements.md)）。**参照してはならない。**

## 3. 算定の流れ

```
①  建築物の類型 × 延べ面積
        ↓  告示の別表（標準業務人・時間数）
②  標準業務人・時間数  [人・時間]
        ↓  × 受託する業務の範囲の割合（基本設計のみ／実施設計を含む／工事監理 …）
③  業務人・時間数  [人・時間]
        ↓  × 人件費単価  [円 / 人・時間]        ← 事務所の設定値
④  直接人件費  [円]
        ↓
⑤  経費 = 直接経費 + 間接経費 = ④ × 経費率      ← 事務所の設定値
⑥  技術料等経費 = (④ + ⑤) × 技術料等経費率      ← 事務所の設定値
⑦  特別経費 = 実費の積上げ（出張旅費、成果物の追加部数 など）
   （告示第670号のみ）検査費 = 実費の積上げ
        ↓
⑧  告示による業務報酬 A = ④ + ⑤ + ⑥ + ⑦（+ 検査費）
        ↓  × 事務所の補正係数、ただし最低報酬額を下回らない
⑨  提示額 B  [円]
        ↓  + 消費税相当額
⑩  税込の提示額
```

> **⑤⑥の掛け方（技術料等経費を直接人件費のみに掛けるか、経費を含めた額に掛けるか）と、
> ②の別表の数値・③の業務区分の割合は、告示の原文から転記する。**
> **本書を書いた時点では告示の原文へ到達できなかったため、上記は費目の構成を示すもので、
> 式の細部は Phase 0 で確定させる**（→ [ROADMAP.md](ROADMAP.md) Phase 0）。
> [CODING_STANDARDS.md §10](CODING_STANDARDS.md) のとおり、**推測を断定形で実装しない。**

### 事務所の設定値（Firestore）

| キー | 内容 | 単位 |
| --- | --- | --- |
| `personnel_unit_price` | 人件費単価。技術者の区分（主任技術者／技術者／技術員）ごとに持つ | 円 / 人・時間 |
| `overhead_rate` | 経費率（直接経費＋間接経費） | 倍率 |
| `technical_fee_rate` | 技術料等経費率 | 倍率 |
| `adjustment_factor` | 業務区分ごとの補正係数 | 倍率（既定 1.0） |
| `minimum_fee` | 業務区分ごとの最低報酬額 | 円 |
| `tax_rate` | 消費税率 | — |

**金額はすべて整数（円）で扱う。浮動小数点を使わない。**
端数処理の丸め位置（円単位／千円単位）と丸め方向は設定値とし、**内訳書に明記する。**

## 4. 補正を「見えるところ」に置く

**告示による算定額 A と、実際の提示額 B を、内訳書に両方出す。**

```
  告示による算定額（令和6年国土交通省告示第8号 略算法）      3,180,000 円
  事務所の補正（補正係数 0.95）                             △ 159,000 円
  ─────────────────────────────────────────
  業務報酬（税抜）                                          3,021,000 円
  消費税相当額                                                302,100 円
  ─────────────────────────────────────────
  合計                                                      3,323,100 円
```

補正の理由を選択式で持ち、内訳書に印字する（例: 既往の設計図書がある／類似案件の実績がある／
業務範囲を限定している／遠方につき現地確認の回数を要する）。

### 補正係数が 1 未満のときは警告を出す

**法22条の3の4は「報酬の基準に準拠し、及び見積書の内容その他の事情を考慮して、
適正な委託代金で契約を締結するよう努めなければならない」と定める**
（→ [01-legal-requirements.md §1.4](01-legal-requirements.md)）。
告示の算定額を大きく下回る提示は、この努力義務に照らして説明を要する。

> 補正係数が 0.95 を下回っています。告示の算定額を下回る理由を内訳書に記載してください
> （法22条の3の4）。

**ブロックはしない。** 努力義務であり、正当な理由がある場合は当然にありうる。
**理由を書かせることに意味がある。**

## 5. 出力: 業務報酬内訳書

雛形は Google ドキュメント。生成の仕組みは契約書と同じ（→ [05-documents.md §2](05-documents.md)）。

**印字するもの**

| 区分 | 内容 |
| --- | --- |
| 適用した基準 | 告示の名称・番号・年月日、略算法によること |
| 前提 | 建築物の類型、延べ面積、構造、階数、受託する業務の範囲 |
| **算定根拠** | 標準業務人・時間数 → 業務人・時間数 → 直接人件費（技術者区分ごとの内訳） |
| 費目の内訳 | 直接人件費／経費／技術料等経費／特別経費（＋告示第670号なら検査費） |
| 補正 | 告示による算定額、補正係数と理由、提示額 |
| 消費税 | 税率、税額、税込合計。端数処理の方法 |
| 有効期限 | 既定30日 |

**「報酬の算定の根拠を明らかにするための見積書」（法24条の10）は、この内訳書がそのまま該当する。**

> **見積書そのもの（宛名・件名・金額のある書式）は、当面マネーフォワード クラウド請求書の
> 画面で作る。** 本ツールが作るのは**内訳書**であり、見積書に添付して送る。
> 見積作成のAPI化は後回しでよい（→ [04-external-services.md §2](04-external-services.md)）。

## 6. 実装の置き場所

**計算は `core/`（Rust → wasm）に置く**（→ [adr/0008](adr/0008-implement-as-portal-tool.md)）。

- **画面が入力のたびに金額を出す。** 面積を動かしながら金額を見られることが、実務では効く
- **保存（内訳書の生成）のとき、サーバが同じ .wasm で計算し直して突き合わせる。**
  食い違えば警告を出す。portal の必要壁量ツールと同じ作法
- 告示の別表は Rust の定数表として持つ。**改正時はテストごと差し替える**

```
core/src/fee_kokuji8.rs     令和6年告示第8号の別表と略算法
core/src/fee_kokuji670.rs   平成27年告示第670号の別表と略算法（検査費を含む）
core/src/fee.rs             共通の費目積算・補正・端数処理
```

### テストで守ること

```
- 告示の別表の値が、原文の表と1つも違わないこと（表を丸ごと突き合わせる）
- 告示に計算例があれば、それを再現できること
- 同じ入力から常に同じ金額が出ること（実務を楽にする、という目的そのもの）
- 端数処理: 円未満が出ないこと、丸め方向が設定どおりであること
- 告示第670号で検査費の費目が立つこと（第8号では立たないこと）
- 補正係数 1.0 のとき、提示額が告示による算定額と一致すること
- 最低報酬額が算定額を上回るとき、最低報酬額が採用され、内訳書にその旨が出ること
```

## 7. 告示の対象外の業務

調査・検査（定期報告等）・手続の代理には業務報酬基準の告示がない。
**実費の積上げ**（業務人・時間数 × 人件費単価 ＋ 経費 ＋ 技術料等経費）で同じ形の内訳書を作る。

- **「告示に準拠」とは書かない。** 根拠のない準拠表示をしない
- 内訳書には「業務報酬基準の告示が定められていない業務であるため、
  当事務所の積算による」と明記する
- **法24条の10の努力義務は、これらの業務にも及ぶ**
  （「設計等の業務に係る契約」＝法23条1項の定義。調査・鑑定を含む。
  → [01-legal-requirements.md §1.5](01-legal-requirements.md)）。
  **書面契約義務が及ばない業務にこそ、見積の努力義務が効く**という非対称を潰さない
