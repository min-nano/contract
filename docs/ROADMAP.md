（→ [05-documents.md §3.3](05-documents.md)）。

> **書面契約は施行前でも適法にできる。** 施行を待つ理由はない。

## Phase 1 — 契約書と重要事項説明書の作成（2026-11 〜 2027-01）

**目標**: 実案件1件の契約書と重要事項説明書を、本ツールで作って交付できる。

### スコープ

- portal に `contract-formatter` を追加する（→ [adr/0008](adr/0008-implement-as-portal-tool.md)）
- **雛形マッピング**（`contract_mapping.json`）。法定記載事項を根拠条文つきで定義する
- **法定記載事項の必須検証**（サーバ側）。欠けていればPDFを作らせない
- **雛形の検証**。必須項目のプレースホルダーが雛形に無ければ**409 で失敗させる**
  （portal の証明書ツールは警告どまり。契約書は止める。→ [05-documents.md §7](05-documents.md)）
- **法定記載事項チェック表**を画面に常設する
- **契約書PDF・重要事項説明書PDFの生成**（雛形の複製 → 置換 → PDF書き出し → 印を描く）
- **入力をPDFの文書情報に埋め込み、開き直して復元する**
- **Drive への保存**（新規作成／開く／保存／別名で保存）。
  既定のファイル名は `YYYYMMDD_取引先名_金額.pdf`
- **義務の適用判定**（契約種別 × 建築士が行う業務か × 相手方が建築主か）
- **メール定型文のコピーボタン**（案件情報を差し込んだ状態で出す）
- 対応する契約種別: **設計受託契約**、**工事監理受託契約**、**設計・工事監理の一括受託**

### スコープ外（意図的に落とす）

- 報酬算定（Phase 2）
- 変更契約（Phase 3）※ **PDFへの入力の埋め込みは Phase 1 でやる。後付けは高くつく**
- 契約台帳、期限アラート（Phase 4）
- 決済、発注者向け画面（**作らない**。→ [adr/0007](adr/0007-document-preparation-only.md)）

### 完了条件

- 実案件1件の契約書と重説書面を本ツールで作り、メールで交付できた
- **必須項目を1つずつ欠いたテストが全件 400 になる**
- **生成したPDFのテキストに、入力した法定記載事項がすべて含まれることをテストで確かめている**
- **生成したPDFを開き直すと、入力が完全に復元される**
- 重説書面で規則17条の38第7号・第8号が空でも生成できる（必須にしていない）

## Phase 2 — 報酬算定と業務報酬内訳書（2027-02 〜 2027-03）

**目標**: 同じ入力からは必ず同じ金額が出る。報酬の算定根拠を示せる。

- **告示の略算法を `core/`（Rust → wasm）に実装する**（→ [06-fee-estimation.md](06-fee-estimation.md)）
  - 令和6年告示第8号（一般）／平成27年告示第670号（耐震診断・改修。**検査費**を持つ）
  - **別表の値が原文と1つも違わないことをテストで固定する**
- 事務所の設定値（人件費単価・経費率・技術料等経費率・補正係数・最低報酬額）を Firestore に置き、
  画面から編集できるようにする
- **画面が入力のたびに金額を出す。** 保存時にサーバが同じ .wasm で計算し直して突き合わせる
- **業務報酬内訳書PDF**の生成。告示による算定額と提示額の**両方**を印字する
- 補正係数が 1 を大きく下回るときの警告（法22条の3の4）
- 告示の対象外の業務（調査・検査・手続の代理）の実費積上げ

> **法24条の10は努力義務であり、施行日に間に合わせる必要はない**
> （→ [01-legal-requirements.md §1.5](01-legal-requirements.md)）。
> Phase 1 が遅れたらこちらを後ろにずらす。

## Phase 3 — 変更契約と契約種別の拡張（2027-04 〜 2027-05）

**目標**: 実務で必ず起きる契約変更と、設計以外の業務に対応する。

- **変更契約書**（法22条の3の3第2項）。原契約PDFを開いて作る（→ [05-documents.md §5](05-documents.md)）
  - 変更前／変更後の対照表を差分から作る
  - 差分が空なら作らせない
- **契約種別の拡張**: 耐震診断、建築物調査・検査（定期報告等）、手続の代理、その他
  - 種別ごとに「書面相互交付の要否」「重説の適用候補」「見積書の推奨」「適用する告示」を切り替える
  - **3つの義務の対象範囲は一致しない**（→ [01-legal-requirements.md §5](01-legal-requirements.md)）
- **元請け設計事務所からの受託**（相手方が建築主でないケース。**重説は不要・書面相互交付は必要**）
- **再委託の記載**（規則17条の38第6号）。
  相手が建築士事務所の開設者であることを入力必須にする（法24条の3第1項）。
  300㎡超の新築工事では一括再委託でないことの確認項目を出す（同2項。**ブロックはしない**）
- **改正法の施行政省令を反映**（記載事項が変われば mapping.json と雛形に反映）
- 全案件を本ツールへ移行

## リスクと対応

| リスク | 影響 | 対応 |
| --- | --- | --- |
| **「相互に交付」をメール返信で構成できない** | 法22条の3の3の履行が不十分。**監督処分の対象** | Phase 0-1 の**最優先**で確認する。否定されれば**紙で2部を交わす**運用に戻す。**ツールが作る書類は変わらない**（印刷すれば紙の契約書になる） |
| **事務処理規程が未整備のまま運用を始める** | **電帳法の真実性を満たす手段がゼロになる** | Phase 0-5 を**リリース前の必須項目**とする。規程・運用・備付けの3つが揃って要件充足（→ [adr/0006](adr/0006-self-hosted-retention.md)） |
| **法定記載事項が印字されないPDFが出来る** | **法定記載事項を欠いた契約書で締結する** | ①サーバ側の必須検証 ②雛形にプレースホルダーが無ければ**409で失敗** ③**生成したPDFのテキストを突き合わせるテスト**（→ [05-documents.md §7](05-documents.md)） |
| **雛形の条項が誰かに書き換えられる** | 意図しない内容で締結する | 雛形フォルダの編集権限を管理建築士に限る。**雛形の更新日時を契約書に印字**する（→ [05-documents.md §2](05-documents.md)） |
| 手順の飛ばし（承諾を取らずに交付する等） | 交付が違法状態になる | チェックリストと、メール定型文をツールが順に出すこと（→ [07-operations.md](07-operations.md)） |
| 契約書の保存し忘れ・保存先の誤り | 電帳法の保存義務違反 | 「作る」と「保存する」が同じ操作になっている。フォルダのルールを規程に書く |
| **保管先（Drive）の誤共有** | 契約書・図面に含まれる個人情報の漏えい | 「リンクを知っている全員」の使用を規程で禁止する（→ [07-operations.md §4.3](07-operations.md)） |
| **告示の別表の転記を誤る** | 見積金額が全件ずれる | 表を丸ごとテストで突き合わせる。告示に計算例があれば再現する（→ [06-fee-estimation.md §6](06-fee-estimation.md)） |
| 施行に伴う政省令改正で記載事項が変わる | mapping と雛形の改修 | 法定記載事項を `contract_mapping.json` の1か所に集約する。**雛形は Google ドキュメントなので、文言の変更はコード変更を伴わない** |
| 改正で法22条の3の3の項番号が繰り上がる（電磁的方法: 4項→3項、24条の8不適用: 5項→4項） | 条文参照が古くなる | 施行時に一括で見直す。条文参照は mapping と本ドキュメントに集約しておく |
| 相手方が承諾しない・撤回する | 電磁的交付ができない | **紙で運用する**（→ [07-operations.md §7](07-operations.md)）。印刷を禁止しないので、同じPDFがそのまま使える |
| portal の変更が契約書ツールを壊す | 契約書が作れなくなる | portal の CI で守る。**法定記載事項のテストを含める** |
| **クラウドBox の API がトライアルのまま、あるいは利用条件が付く** | 自動アップロードが作れない／作った後に止まる | **既定は Drive ＋事務処理規程。** Box に依存した設計をしない。**Box を使うこと自体は手作業で成立する**ので、API が使えなくても保存の運用は変わらない（→ [04-external-services.md §3](04-external-services.md)） |
| 施行期日政令が想定より早い日を指定する | 移行が間に合わない | Phase 1 が設計受託・工事監理受託だけで完結する。**Phase 2・3 を後ろにずらせば、契約書の作成だけは先に回る** |
