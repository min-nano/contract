# 法令要件（建築士法）

本システムが満たすべき法令要件を条文ベースで整理する。
実装時の「必須項目」「必須フロー」はすべてここを一次情報とする。

> 条文は e-Gov 法令検索 API から取得（建築士法 昭和25年法律第202号 / 建築士法施行令 昭和25年政令第201号 /
> 建築士法施行規則 昭和25年建設省令第38号）。改正法の施行に伴い条文番号・内容が変わるため、
> 施行政省令の公布時に本書を必ず再検証すること（→ [ROADMAP.md](ROADMAP.md) Phase 0）。

## 1. 改正建築士法（2026年成立）の影響

| 項目 | 現行 | 改正後 |
| --- | --- | --- |
| 書面契約義務の対象 | 延べ面積300㎡**超**の建築物の**新築**に係る設計受託契約・工事監理受託契約（法22条の3の3第1項）※増築・改築・大規模の修繕・大規模の模様替は当該部分の新築とみなす（同条3項） | **面積要件を撤廃**し、建築士が行うすべての設計受託契約・工事監理受託契約 |
| 見積書 | 規定なし（報酬基準準拠の努力義務のみ／法22条の3の4） | 建築士事務所の開設者に**報酬の根拠を明らかにする見積書の作成**を義務付け |
| 成立日 | — | 2026年7月24日（参議院本会議可決） |
| 施行 | — | 契約適正化関係は**公布から1年以内** |

**設計方針への影響**

1. 面積・用途による分岐を**業務ロジックに持たせない**。全案件を書面契約対象として扱う。
   （現行法下でも300㎡以下に書面契約をしても違法ではないため、施行前から先行適用できる）
2. 見積書は「報酬の根拠」を示せる構造化データとして保持する。
   金額の総額だけでなく、**業務報酬基準（令和6年国土交通省告示第8号、2024年1月9日公布・施行、
   平成31年告示第98号は廃止）** に基づく算定根拠（略算法の区分・床面積・業務人・時間数など）を
   項目として持てるようにする。
3. 300㎡という数値は**設定値としても持たない**。現行法の条文タイトルに残るのみ。

## 2. 契約書面の法定記載事項

### 2.1 法22条の3の3第1項（相互交付する契約書面）

契約当事者は、契約の締結に際して次の事項を書面に記載し、**署名又は記名押印をして相互に交付**しなければならない。

| # | 根拠 | 記載事項 | 適用 |
| --- | --- | --- | --- |
| 1 | 1項1号 | 作成する設計図書の種類 | 設計受託契約 |
| 2 | 1項2号 | 工事と設計図書との照合の方法／工事監理の実施の状況に関する報告の方法 | 工事監理受託契約 |
| 3 | 1項3号 | 当該設計又は工事監理に従事する建築士の氏名、一級/二級/木造の別、構造設計一級建築士・設備設計一級建築士である場合はその旨 | 共通 |
| 4 | 1項4号 | 報酬の額及び支払の時期 | 共通 |
| 5 | 1項5号 | 契約の解除に関する事項 | 共通 |
| 6 | 1項6号 → 規則17条の38 | 下表のとおり | 共通 |

### 2.2 規則17条の38（省令で定める事項）

| # | 記載事項 |
| --- | --- |
| 6-1 | 建築士事務所の名称及び所在地、一級/二級/木造建築士事務所の別 |
| 6-2 | 建築士事務所の開設者の氏名（法人の場合は名称及び代表者の氏名） |
| 6-3 | 契約の対象となる建築物の概要 |
| 6-4 | 業務に従事する建築士の登録番号 |
| 6-5 | 業務に従事する建築設備士がいる場合はその氏名 |
| 6-6 | 設計又は工事監理の一部を委託する場合は、委託に係る業務の概要、受託者の氏名又は名称、受託者に係る建築士事務所の名称及び所在地 |
| 6-7 | 設計又は工事監理の実施の期間 |
| 6-8 | 6-3〜6-6のほか、設計又は工事監理の種類、内容及び方法 |

### 2.3 変更契約（法22条の3の3第2項）

上記各号に該当する内容を変更するときは、**変更の内容を書面に記載し、署名又は記名押印をして相互に交付**する。
→ 実務上ほぼ必ず発生する（設計変更・工期変更・報酬変更）。**MVP段階から変更契約を想定した
データモデル（契約のバージョン管理）にしておく**こと。後付けは高くつく。

### 2.4 24条の8書面との関係

法24条の8第1項は、契約締結後に開設者から委託者へ書面を交付する義務。
ただし**法22条の3の3第5項により、1項の書面を相互に交付した場合は24条の8第1項は適用されない**。

したがって本システムは **22条の3の3の「相互交付」を正とし、24条の8書面は発行しない**。
ただし相互交付が成立しない場合（相手方が電子署名を拒否した等）のフォールバックとして
24条の8書面の交付経路を残す。24条の8書面には規則22条の3により次が追加で必要:

- 契約の年月日
- 契約の相手方の氏名又は名称
- 開設者の**記名押印又は署名**（規則22条の3第2項）

なお、契約の年月日と相手方の氏名は 22条の3の3 書面でも実務上必須なので、
データモデル上は常に保持する。

## 3. 重要事項説明（法24条の7）

**契約締結より前**（「あらかじめ」）に、開設者は**管理建築士等**（管理建築士その他その事務所に属する建築士）
をして、建築主に対し書面を交付して説明させなければならない。

### 3.1 記載事項

法22条の3の3第1項1号〜5号と同一の5項目 ＋ 規則22条の2の2により **規則17条の38第1号〜第6号**。

> **注意**: 重要事項説明書の省令事項は 17条の38 の **1号〜6号のみ**であり、
> **7号（実施の期間）・8号（種類、内容及び方法）は含まれない**。
> 契約書面と重説書面はフィールド集合が異なる。実装では別スキーマとして定義すること。
> （実務上は重説書面に7号8号相当を任意記載しても差し支えないが、必須判定を共通化してはならない。）

### 3.2 免許証の提示（24条の7第2項）

管理建築士等は説明時に**建築士免許証（又は免許証明書）を提示**しなければならない。

→ **画面上の書面閲覧だけでは重要事項説明を履行したことにならない。**
説明という行為と免許証の提示が必要。本システムは以下を担う:

- 重説書面（PDF）の生成と事前交付
- 説明の実施記録（実施日時、説明者＝管理建築士等の氏名・資格・登録番号、実施方法［対面／ビデオ通話］、
  免許証の提示方法、建築主の受領・了解の記録）を監査ログとして保存
- 説明未実施の場合、契約締結ステップへ進めないガード

ビデオ通話による説明（いわゆるIT重説）を行う場合は、映像・音声が明瞭であること、
免許証が画面上で判読可能であることを運用要件として定め、実施記録に残す。
建築士法にIT重説の明文規定はないため、**運用ルールとして法務レビューを受けること**（Phase 0）。

## 4. 電磁的方法による交付の要件

書面交付に代えて電磁的方法で提供できるが、以下をすべて満たす必要がある。
本システムの電子契約フローの中核要件。

### 4.1 相手方の承諾が必須（令8条 → 令7条準用）

| 対象 | 根拠 |
| --- | --- |
| 22条の3の3書面（契約書面） | 法22条の3の3第4項、令8条1項 |
| 24条の7書面（重説書面） | 法24条の7第3項、令8条2項 |
| 24条の8書面 | 法24条の8第2項、令8条3項 |

承諾の取得手順（令7条準用）:

1. **あらかじめ**、相手方に対し**用いる電磁的方法の種類及び内容を示す**
   - 示すべき内容は規則17条の40 / 22条の2の4 / 22条の5:
     ① 規則で定める方法のうち当事者が使用するもの、② **ファイルへの記録の方式**（＝ファイル形式。PDF等）
2. 相手方から**書面又は情報通信の技術を利用する方法**（規則17条の41 / 22条の2の5 / 22条の5の2）で承諾を得る
3. 承諾を得た後でも、相手方から**電磁的方法による提供を受けない旨の申出**があった場合は
   電磁的方法で提供してはならない（令7条2項）。再度承諾を得た場合を除く。

→ **実装要件**
- 電子契約フローの最初のステップを「電磁的方法による交付の承諾」画面とする。
  同画面で「方法の種類（電子情報処理組織を使用する方法／閲覧に供する方法）」と
  「ファイルへの記録の方式（PDF）」を明示する。
- 承諾の記録（表示した種類・内容の全文スナップショット、承諾日時、IPアドレス、User-Agent）を保存する。
- **承諾の撤回（受けない旨の申出）を受け付けるUI**と、撤回後に電磁的交付をブロックする状態遷移を実装する。
  撤回された場合は紙面交付フローへ切り替える。
- 承諾は契約ごとに取得する（包括承諾の可否は法務レビュー事項）。

### 4.2 提供方法の技術基準（規則17条の39 / 22条の2の3 / 22条の4）

| # | 基準 | 実装での担保 |
| --- | --- | --- |
| 1 | 相手方が**ファイルへの記録を出力することにより書面を作成できる**こと | PDFをダウンロード・印刷可能にする。DRM・印刷禁止・閲覧期限による恒久的なアクセス遮断をしない。締結後PDFを相手方に確実に渡す（メール添付＋ダウンロードリンク） |
| 2 | 記録された事項について**改変が行われていないかどうかを確認することができる措置**（重説書面は「改変を**防止**するための措置」と文言が異なる） | 電子署名＋タイムスタンプ（マネーフォワード クラウド契約の長期署名）。重説書面は当事務所の電子署名または改ざん検知可能な形式で交付し、ハッシュ値を監査ログに記録 |
| 3 | 「閲覧に供する方法」（1項1号ロ）を採る場合、**記録した旨を相手方に通知**すること。ただし相手方が閲覧していたことを確認したときは不要 | 書面をアップロードした時点で通知メールを送信し、送信記録と閲覧記録の双方を保存 |

> 本システムは「① 電子情報処理組織を使用する方法」を採用し、ロ（閲覧に供する方法）に該当する運用となるため、
> **通知メールの送信は必須**である。通知の送達記録（メッセージID、送信日時、bounce有無）を保存すること。

### 4.3 印紙税

電子契約（課税文書の「作成」＝紙の交付に当たらない）は印紙税の課税対象外。
設計・工事監理受託契約は請負に関する契約書（第2号文書）に該当しうるため、
電子化によるコスト削減効果は大きい。ただし**変更契約書面についても電子で完結させる**こと
（一部を紙に戻すと課税される）。

## 5. 契約種別ごとの適用範囲（汎用性の設計根拠）

建築士法22条の3の3・24条の7・24条の8が適用されるのは
**設計受託契約**および**工事監理受託契約**に限られる。

| 契約種別 | 建築士法の書面義務 | 重要事項説明 | 備考 |
| --- | --- | --- | --- |
| 設計受託契約 | ○（改正後は全件） | ○ | 新築・増築・改築・大規模の修繕・大規模の模様替 |
| 工事監理受託契約 | ○（改正後は全件） | ○ | |
| 建築物調査・検査（定期報告等） | × | × | 建築基準法12条関係。社内標準として同等の記載を採用 |
| 耐震診断 | × | × | 耐震改修促進法関係。診断に伴う設計は設計受託契約として別途 |
| その他コンサルティング | × | × | |

**設計方針**: 契約種別を第一級の概念（`ContractType`）とし、
種別ごとに「法定必須項目セット」「重説要否」「テンプレート」「入力スキーマ」を持たせる。
建築士法適用種別は必須項目を強制し、非適用種別は同じ枠組みで任意項目として扱う。
→ [docs/03-architecture.md](03-architecture.md) のデータモデルを参照。

## 6. 建築士法以外に検討が必要な法令

MVPのスコープ外だが、Phase 2（決済・BtoC）までに整理が必要。

| 法令 | 論点 | 対応時期 |
| --- | --- | --- |
| 消費者契約法 | 発注者が一般消費者の場合の不当条項規制。解除・違約金条項の平均的損害を超える部分は無効 | Phase 2 までに契約書雛形を法務レビュー |
| 特定商取引法 | オンラインで申込みを受ける形態が通信販売に該当するか。該当する場合は「特定商取引法に基づく表記」「申込確認画面（最終確認画面）」の表示義務。**訪問販売に該当する場合はクーリング・オフの対象になりうる**（現地打合せで契約した場合など）ため要検討 | Phase 2 |
| 電子帳簿保存法 | 電子取引データ（契約書・見積書・請求書）の保存要件。真実性（タイムスタンプ or 訂正削除の記録が残るシステム）と可視性（検索要件: 取引年月日・取引金額・取引先） | Phase 1 から検索キーを設計に織り込む |
| 個人情報保護法 | 建築主の氏名・住所・建物所在地・図面。安全管理措置と委託先管理（MF、Stripe、Clerk、GCP） | Phase 0 で委託先一覧と個人情報取扱規程を整備 |
| 電子署名法 | 2条・3条の要件。事業者署名型（立会人型）の推定効については利用者の指示の記録が重要 | MFの仕様に依存。Phase 0 で確認 |
| 下請法 / 建設業法 | 設計業務の一部を再委託する場合（規則17条の38第6号に関連） | Phase 3 |
