# 運用（システムが担わない部分）

[adr/0007](adr/0007-document-preparation-only.md) により、**承諾・交付・受領・説明・保管は
すべて運用で行う。** 本書はその手順・定型文・規程を定める。

**運用で賄うと決めた以上、「気をつける」で済ませない。**
手順は書き出し、文面は用意し、規程は備え付ける。**それが要件充足の実体である。**

---

## 1. 全体の手順

```
[事務所]                                        [相手方]

  ① 電磁的方法による交付の承諾を求める ────→  メール受信
     （定型文 A。令8条→令7条準用）              │
                                        承諾の返信 ←┘
  ─────────────── 承諾が取れるまで、電磁的方法で書面を送らない ───────────────

  ② 見積書＋業務報酬内訳書を送る（努力義務）─→  検討
     （ツールで内訳書を作る）

  ③ 重要事項説明書を作り、事前に送る ───────→  受領
     （定型文 B。※ 相手方が建築主の場合のみ）
        ↓
  ④ 重要事項の説明を行う（対面／ビデオ通話）
     免許証を提示する
     実施記録の欄を埋め、建築主の署名をもらう
     ────────────────────────────────────────────
     ここまでが「契約の締結前」。順序を入れ替えない（法24条の7「あらかじめ」）
     ────────────────────────────────────────────

  ⑤ 契約書を作り、双方の氏名を印字して送る ─→  受領・内容確認
     （定型文 C）                                │
                                    同意と交付の返信 ←┘（定型文 D をコピーして返信）
        ↓
  ⑥ 相互交付の成立。契約書PDFと、往復したメールを保存する
        ↓
  ⑦ 保存（→ §4）。請求はマネーフォワード クラウド請求書で行う
```

> **③④は相手方が建築主の場合のみ。** 元請けの設計事務所から受託する場合、
> 重要事項説明の義務はない（法24条の7第1項「建築主と締結しようとするとき」）。
> **一方、書面の相互交付（法22条の3の3）は建築主に限られないので①⑤⑥は必要**
> （→ [01-legal-requirements.md §3.0](01-legal-requirements.md)）。

## 2. メールの定型文

**ツールの画面にコピーボタンとして置く。** 案件の情報（相手方の氏名、書類名、作成日、頁数）を
差し込んだ状態で出す。**手で書き起こさせない。**

### 定型文 A — 電磁的方法による交付の承諾を求める

> **件名**: 【ご確認のお願い】契約書面等の電磁的方法によるご提供について
>
> ＿＿＿＿ 様
>
> 当事務所は、建築士法に基づき交付する書面（設計等業務委託契約書・重要事項説明書）を、
> 書面（紙）の交付に代えて電磁的方法によりご提供したいと考えております。
> 建築士法施行令第8条の規定により、あらかじめ次の事項をお示しし、
> ご承諾をいただく必要があります。
>
> **1. 用いる電磁的方法の種類**
> 　電子メールに添付してファイルを送信し、お客様のパソコン等のファイルに
> 　記録していただく方法
>
> **2. ファイルへの記録の方式**
> 　PDF形式（Portable Document Format）
>
> ご承諾いただける場合は、本メールにご返信のうえ、次の一文をそのままお送りください。
>
> 　「上記の電磁的方法により、契約書面及び重要事項説明書の提供を受けることを承諾します。」
>
> ご承諾いただいた後であっても、**電磁的方法による提供を受けない旨のお申し出**を
> いただくことができます（建築士法施行令第7条第2項の準用）。
> お申し出をいただいた場合は、書面（紙）でのお渡しに切り替えます。
>
> 本メールはそのまま印刷して保存していただけます。

**押さえている要件**

| 要件 | 根拠 | 本文のどこ |
| --- | --- | --- |
| あらかじめ承諾を得る | 令8条 → 令7条準用 | 全体 |
| 用いる電磁的方法の**種類**を示す | 規則17条の40 / 22条の2の4 | 1. |
| **ファイルへの記録の方式**を示す | 同上 | 2. |
| 承諾を書面又は情報通信の技術を利用する方法で得る | 規則17条の41 / 22条の2の5 | 返信文 |
| **承諾の内容を書面により出力できる** | 規則22条の2の5（重説） | 末尾の一文 |
| 受けない旨の申出の受付 | 令7条2項 | 撤回の案内 |

> **この承諾が取れるまで、契約書面・重説書面を電磁的方法で送ってはならない。**
> 承諾なく電磁的方法で提供した場合、**書面を交付したものとみなされない**（令8条）。
> つまり交付義務を果たしていないことになる。**監督処分の対象である。**

### 定型文 B — 重要事項説明書の事前交付

> **件名**: 【事前送付】重要事項説明書のご確認のお願い（＿＿＿＿ 様邸 新築設計）
>
> ＿＿＿＿ 様
>
> 設計受託契約の締結に先立ち、建築士法第24条の7の規定に基づく
> **重要事項説明書**を添付のとおりお送りいたします（PDF形式・全＿頁）。
>
> 本書面の内容につきましては、**管理建築士 ＿＿＿＿ が改めてご説明**いたします。
> ご都合のよい日時をお知らせください（対面またはビデオ通話）。
>
> ビデオ通話をご希望の場合は、あらかじめご意向を確認させていただくとともに、
> ご利用の機器・ソフトウェアについてもご相談させてください。
> 説明の際は、建築士免許証を提示いたします。
>
> **説明の前に本書面をお手元でご確認いただける状態**にしていただきますよう
> お願いいたします。

> **「送った」だけでは義務を果たしていない。** 法24条の7は説明を求めており、
> 同条2項は免許証の提示を求めている（→ [01-legal-requirements.md §3](01-legal-requirements.md)）。
> 実施記録は重説書面の末尾の欄に残す（→ [05-documents.md §6](05-documents.md)）。

### 定型文 C — 契約書の交付

> **件名**: 【ご確認のお願い】設計等業務委託契約書のご送付（＿＿＿＿ 様邸 新築設計）
>
> ＿＿＿＿ 様
>
> 先般ご承諾いただきました電磁的方法により、
> **設計等業務委託契約書**を添付のとおりお送りいたします。
>
> 　ファイル名: 20270415_＿＿＿＿_3300000.pdf
> 　形式・頁数: PDF形式・全＿頁
> 　作成年月日: 令和＿年＿月＿日
>
> 建築士法第22条の3の3第1項は、契約書面を**当事者が相互に交付する**ことを
> 定めております。つきましては、内容をご確認のうえ、
> **本メールに添付の契約書PDFをそのまま添付して**ご返信いただき、
> あわせて次の一文をお送りくださいますようお願いいたします。
>
> ────────────────────────────────
> 　別添の「設計等業務委託契約書」（PDF形式、令和＿年＿月＿日作成、全＿頁、
> 　ファイル名 20270415_＿＿＿＿_3300000.pdf）に記載された事項について、
> 　電磁的方法により貴事務所へ提供し、同書面の内容で契約を締結することに
> 　同意します。
> 　　　令和＿年＿月＿日　　氏名 ＿＿＿＿＿＿＿＿
> ────────────────────────────────
>
> 添付ファイルの再送信が難しい場合は、上記の一文のみをご返信ください。
>
> ご不明な点、記載内容の相違がございましたら、ご返信前にお知らせください。
> 修正のうえ改めてお送りいたします。

### 定型文 D — 相手方に返信してもらう文（Cに埋め込み済み）

**相手方は「同意する」だけでなく「提供する（交付する）」と書く必要がある。**
法22条の3の3第1項は**相互に交付**することを求めており、
事務所からの一方向の送付では条文を満たさない（→ §3）。

## 3. 相互交付をどう成立させるか — **最大の未確定事項**

**「PDFをメールで送り、本文で同意をもらう」という運用が、
法22条の3の3第1項の『相互に交付』を満たすかは確認できていない。**

| 事実 | 状況 |
| --- | --- |
| 電磁的方法による提供に**電子署名は要らない** | **確認済み**（→ [01-legal-requirements.md §4.2.1](01-legal-requirements.md)、[adr/0005](adr/0005-electronic-signature-requirement.md)） |
| 改変への措置は **PDF形式で足りる** | **確認済み**（国交省の明示。→ [01-legal-requirements.md §4.2.3](01-legal-requirements.md)） |
| **相手方からの交付**をどう構成するか | **未確認。Phase 0 の法務レビューの最優先事項** |

**押さえておくべき区別**

- **契約の成立**（民法）と、**法22条の3の3の履行**は別である。
  設計受託契約は諾成契約なので合意だけで成立し、書面の相互交付は成立要件ではない。
  **交付を怠っても契約は有効だが、監督処分（戒告・1年以内の閉鎖命令・登録取消）の対象になる**
  （法26条2項1号）。「同意をもらえば契約は成立する」は正しいが、**義務を果たしたことにはならない。**
- **法24条の8書面では代替できない。** 法22条の3の3第5項（改正後4項）は
  「相互に交付したときは24条の8第1項を適用しない」という向きの規定であり、
  逆は成り立たない。**相互交付は避けて通れない。**

**したがって運用は、相手方からの提供を明示的に取りに行く形にする。**

| 段階 | 内容 |
| --- | --- |
| **既定** | 相手方が**同一の契約書PDFを添付して返信**し、あわせて「電磁的方法により貴事務所へ提供し…同意します」の一文を送る（定型文 C）。これが最も交付の実質に近い |
| **次善** | 添付なしで、書面を特定できる情報（ファイル名・作成日・頁数）を引用した**一文のみ**を返信してもらう |
| **フォールバック** | 上記が成立しないと判断される場合、**紙の契約書を2部作成し、双方が署名又は記名押印して1部ずつ保有する**（従来の実務） |

> **フォールバックに落ちても、ツールの設計は何も変わらない。**
> 作るのは同じ契約書PDFであり、印刷して署名するだけである。
> **この論点はツールの実装を止めない。**

## 4. 保存

### 4.1 何を、どこに保存するか

| 書類 | 保存の根拠 | 保存先 | 保存期間 |
| --- | --- | --- | --- |
| **契約書PDF**（変更契約書を含む） | **電子帳簿保存法**（電子取引の取引情報）＋建築士法の履行の証跡 | Drive の契約書類フォルダ | 電帳法の保存期間に従う（**事務所の形態［法人／個人事業］で年数が変わるため、Phase 0 で確定させる**） |
| **重要事項説明書PDF**（実施記録を含む） | 建築士法24条の7の履行の証跡（**監督処分の対象**） | 同上 | **契約書に合わせる**（法定の期間はないが、処分の除斥期間を考えれば短くしない） |
| **見積書・業務報酬内訳書** | 電子帳簿保存法（電子取引） | 同上 | 契約書と同じ |
| **往復したメール**（承諾・交付・同意の返信） | 交付と承諾を示す唯一の証跡 | **Google Workspace のメールボックス**。削除しない | 契約書と同じ |
| 紙で交わした契約書 | 同上 | **紙のまま保管**（→ §4.4） | 同上 |

> **重説書面は電子帳簿保存法の対象ではない**（取引情報を記載した書類ではない）。
> **建築士法上の義務の履行を示す証跡**として保存する。
> 根拠が違うので、規程では**別の節に書く。**

#### 建築士法24条の4（帳簿の備付け等及び図書の保存）

**契約書類の保存とは別の義務である。【原文照合済み 2026-08-17】**（規則21条）

| | 内容 | 保存期間 |
| --- | --- | --- |
| **業務に関する帳簿**（法24条の4第1項） | 下表の8項目。**電子計算機のファイル等に記録し、事務所で明確に紙面に表示できるなら、帳簿への記載に代えられる**（規則21条2項） | **各事業年度の末日をもって閉鎖し、閉鎖の日の翌日から起算して15年間**（同3項） |
| **設計図書等**（法24条の4第2項） | 配置図・各階平面図・二面以上の立面図・二面以上の断面図・基礎伏図・各階床伏図・小屋伏図・構造詳細図、構造計算に係る図書、令46条4項／47条1項等への適合を確認できる図書、**工事監理報告書**ほか（規則21条4項） | **作成した日（受領した図書は受領した日）から起算して15年間**（同5項） |

**帳簿の記載事項（規則21条1項）**

| # | 記載事項 | 契約書ツールの入力にあるか |
| --- | --- | --- |
| 一 | 契約の年月日 | **ある**（`contract_date`） |
| 二 | 契約の相手方の氏名又は名称 | **ある**（`counterparty_name`） |
| 三 | 業務の種類及びその概要 | **ある**（`work_type_content_method`） |
| 四 | 業務の終了の年月日 | ない（業務の完了後に分かる） |
| 五 | 報酬の額 | **ある**（`fee_amount`） |
| 六 | 業務に従事した建築士及び建築設備士の氏名 | **ある**（`architects[]` / `equipment_architect_name`） |
| 七 | 業務の一部を委託した場合の、委託に係る業務の概要並びに受託者の氏名又は名称及び住所 | **ある**（`subcontracts[]`。ただし帳簿は**住所**、契約書面は**事務所の名称及び所在地**） |
| 八 | 法24条4項の意見が述べられたときは、その概要 | ない |

> **8項目のうち6つは契約書ツールの入力そのものである。**
> ファイル名規則（§4.2）も契約の年月日・相手方・報酬の額を持つ。
> **当面は帳簿を運用（表計算）で作り**、件数が増えたら契約書PDFから帳簿を組み立てる
> 機能を足す（→ portal の
> [docs/contract-formatter.md §11](https://github.com/min-nano/portal/blob/main/docs/contract-formatter.md)
> Phase 4）。**先に作らない。**
>
> **保存期間15年は、電帳法の保存期間より長い。** 契約書類フォルダの保存ルールは
> **長いほうに合わせる**のが安全である。

### 4.2 フォルダとファイル名

```
契約書類/                          ← 共有: 管理建築士のみ（→ §4.3）
  2027/
    20270415_山田太郎_住宅新築設計/
      20270415_山田太郎_3300000.pdf              契約書
      20270401_山田太郎_重要事項説明書.pdf        重説（交付した版）
      20270405_山田太郎_重要事項説明書_説明済.pdf  重説（実施記録を埋めた版）
      20270320_山田太郎_業務報酬内訳書.pdf
      メール/                                     承諾・交付・同意の返信（PDF化して保存）
```

**契約書・見積のファイル名は `YYYYMMDD_取引先名_金額.pdf` に従う。**

- 電子帳簿保存法の検索要件（取引年月日・取引金額・取引先）への備え。
  **小規模事業者の特例で検索要件が外れる見込み**だが（→ [03-architecture.md](03-architecture.md)）、
  該当しなくなったときに遡って直すのは現実的でない
- **ツールが既定のファイル名としてこの形を組み立てる。** 手で付けさせない
- 重説書面には金額がないため、この規則の対象外（電帳法の対象ではないため）

### 4.3 共有設定のルール

**契約書と図面には、氏名・住所・建物の所在地といった個人情報が含まれる。**

| ルール | 内容 |
| --- | --- |
| **「リンクを知っている全員」を使わない** | **例外なく禁止。** 誤操作の1クリックで公開される |
| 共有は**個人のアカウントを指定して**行う | グループ共有を使う場合、そのグループの構成員を年1回棚卸しする |
| 契約書類フォルダの編集権限は**管理建築士のみ** | 所員には必要なフォルダだけを閲覧権限で共有する |
| **雛形フォルダの編集権限も管理建築士のみ** | 条項が書き換わると、意図しない内容で締結してしまう（→ [adr/0008](adr/0008-implement-as-portal-tool.md)） |
| 発注者とは**このフォルダを共有しない** | 交付はメール添付で行う。共有フォルダを交付経路にしない |

**個人情報取扱規程に含める。**

### 4.4 電子帳簿保存法への対応

**保存が事務所の手元にある以上、要件の満たし方は
[adr/0006](adr/0006-self-hosted-retention.md) の整理をそのまま引き継ぐ。**

#### 真実性 — 規則4条1項4号（事務処理規程）が唯一の手段

| # | 措置 | 採否 |
| --- | --- | --- |
| 1 | タイムスタンプが付された後に授受 | — |
| 2 | 授受後速やかにタイムスタンプを付す | 有償の認定時刻認証業務が要る（規則2条6項2号ロ）。→ ただし**§4.5 の選択肢がありうる** |
| 3イ | 訂正削除の事実及び内容を確認できるシステムで**授受及び保存**を行う | **使えない。** 条文が保存もそのシステムで行うことを求めており、Drive での保存はこれに当たらない |
| 3ロ | 訂正削除を行うことができないシステム | 同上 |
| **4** | **正当な理由がない訂正及び削除の防止に関する事務処理の規程**を定め、規程に沿った運用を行い、規程の備付けを行う | **採用。唯一の手段** |

> ⚠ **これはリリースのブロッカーである。** 規程が未整備のまま運用を始めると、
> **真実性の要件を満たす手段がゼロになる。** 規程を作っただけでは足りず、
> **運用と備付け**まで揃って要件充足になる。

#### 可視性 — 小規模事業者の特例で検索要件が外れる見込み

規則4条1項の柱書は、**基準期間の売上高が5,000万円以下**の事業者であって、
**電磁的記録の提示等の要求に応じることができるようにしているとき**は
検索要件を除く、と定める。**1名の建築士事務所は該当する見込みが高い。**

備えとして §4.2 のファイル名規則を運用に入れる。
ディスプレイ・プリンタの備付けと整然・明瞭な出力は、Drive のプレビューと印刷で満たす。

#### 紙で交わした分

**スキャナ保存の要件（解像度200dpi以上・256階調以上・タイムスタンプ）は負担が大きい。
紙は紙のまま保存する**を既定とする。電子化は将来の検討事項とする。

> 電子化するなら クラウドBox が**スキャナ保存区分に対応している**（→ §4.5）。
> ただし**負担は Box 側ではなく読み取り側にある**（契約書は「重要書類」なのでカラー必須）。
> 紙で交わす案件が実際に出てから考える。

### 4.5 マネーフォワード クラウドBox を使う場合

**クラウドBox は電子取引データ保存区分・スキャナ保存区分に対応している**
（→ [04-external-services.md §3](04-external-services.md)。2026-08-17 に公式ページで確認）。
**Box に上げる運用にすれば、真実性の確保が「規程の運用」から「Boxへ上げる」に移る。**

- タイムスタンプは**アップロード時に付与される仕組み**
- 訂正・削除の防止は、**該当ファイルを削除できない仕様**で満たしている
- **契約書PDFは「電子で授受した書類」**に当たり、対応範囲に収まる

**手で上げる運用なら、今日から使える。** ツールは PDF を作って Drive へ保存するだけで、
**Box へは手で上げても成立する。**

> **自動アップロード（API 連携）は別の話である。**
> API は 2025年11月に提供が始まったが、**トライアルとしての提供**であり、
> 「今後、利用条件等を設ける場合があります」と明記されている。開発者サイトにも
> 仕様書が載っていない。**トライアルの API に日々の保存を載せると、条件が付いた時点で
> 止まる。** 自動化は Phase 0-6 で仕様と利用条件を確認してから判断する
> （→ [ROADMAP.md](ROADMAP.md)）。

> **Box を使うことにしても、事務処理規程は作る。**
> ①紙で交わした分と手書きの控えが残る ②Box の障害・仕様変更に備える
> ③規程の備付け自体は負担が小さい —— の3点による。
> **したがって、規程の整備がリリースのブロッカーであることは変わらない。**

## 6. 電子取引データの訂正及び削除の防止に関する事務処理規程（骨子）

**規則4条1項4号に基づく規程。Phase 0 で制定する。**
国税庁が公表するサンプルを土台に、次の点を事務所の実態に合わせる。

| 条 | 内容 | 本事務所での定め方 |
| --- | --- | --- |
| 目的 | 電子取引の取引情報に係る電磁的記録の適正な保存 | — |
| 適用範囲 | 対象となるデータ | **契約書・変更契約書・見積書・業務報酬内訳書・請求書**（PDF）。往復メールを含む |
| 管理責任者 | 誰が責任を負うか | **管理建築士**。1名事務所では兼務であることを明記する |
| 保存場所 | どこに保存するか | **Google Drive の「契約書類」フォルダ**（→ §4.2）。パスを明記する |
| ファイル名 | 検索できる形にする | **`YYYYMMDD_取引先名_金額.pdf`**（→ §4.2） |
| **訂正削除の原則禁止** | 保存したデータを訂正・削除しない | **原則禁止**を明記する |
| **やむを得ない場合の手続** | 誰の承認で、何を記録するか | 管理責任者の承認を要する。**訂正削除の年月日・対象・理由・処理内容を「訂正削除記録簿」に記載**し、規程とあわせて保存する |
| 誤って保存したデータの扱い | 差し替えの手順 | 元のファイルを残したまま、訂正版を別ファイル（`_訂正` を付す）として保存し、記録簿に理由を書く |
| 保存期間 | いつまで | 電帳法の保存期間（原則7年）に合わせる |
| **規程の備付け** | どこに置くか | **保存場所と同じフォルダに規程のPDFを置く。** 規則4条1項4号は「当該電磁的記録の保存に併せて当該規程の備付けを行うこと」と定めている |

**別に定めるもの**

- **重要事項説明書・説明の実施記録の保存**（建築士法の証跡。電帳法とは根拠が違う）
- **個人情報取扱規程**（保管先の共有設定ルールを含む。→ §4.3）
- **委託先の一覧**（Google Workspace / Google Cloud / Clerk / マネーフォワード）と、
  安全管理措置の確認記録（個人情報保護法）

> **規程は作って終わりではない。** 規則4条1項4号が求めるのは
> ①規程を定めること ②**規程に沿った運用を行うこと** ③**規程の備付けを行うこと**の3つである。
> 訂正削除記録簿が1度も使われないのは正常だが、**簿冊そのものは用意しておく。**

## 7. 承諾が得られない・撤回された場合

**電磁的方法による提供を受けない旨の申出があったら、以後は電磁的方法で提供してはならない**
（令7条2項の準用）。再度承諾を得た場合を除く。

| 状況 | 対応 |
| --- | --- |
| 最初から承諾が得られない | **紙で運用する。** 契約書を2部印刷し、双方が署名又は記名押印して1部ずつ保有する |
| 交付後に撤回された | 撤回以後の書面（変更契約書など）を紙で交付する。**既に適法に交付した書面は有効** |
| 紙で交わした契約書の保存 | **紙のまま保存する**（→ §4.4） |

**ツールが作るPDFは、印刷すればそのまま紙の契約書になる。**
印刷・テキスト抽出を禁止しない（→ [adr/0007](adr/0007-document-preparation-only.md)）のは
法令要件であると同時に、この経路のためでもある。
