# contract — 建築士事務所の契約書類 作成支援

建築士事務所が締結する設計等業務委託契約について、
**法定記載事項を漏らさない契約書・重要事項説明書を作り、報酬を算定する**ための設計文書。

**このリポジトリに実装は置かない。**
実装は社内ポータル（[portal](https://github.com/min-nano/portal)）のツールとして行う
（→ [docs/adr/0008](docs/adr/0008-implement-as-portal-tool.md)）。
ここに残るのは、**法令要件・書類の仕様・報酬算定の仕様・運用の手順**である。

## なぜ作るか

**建築士法の一部を改正する法律（令和8年法律第74号）が令和8年（2026年）7月31日に公布された。**
書面契約義務の面積要件（延べ面積300㎡超の新築）が撤廃され、
**建築士が行う設計・工事監理の委託を受けるすべての契約が書面の相互交付の対象**になる（法22条の3の3）。
施行は**公布から1年以内**、すなわち**遅くとも2027年7月31日**（施行日は政令で定まる）。

小規模案件（住宅など300㎡以下）を含む全案件で、法定記載事項を満たした契約書面と
重要事項説明書を作る必要がある。**紙の運用では回らない。**

あわせて、報酬の算定の根拠を明らかにするための見積書の作成が求められる
（法24条の10。ただし**努力義務**）。**見積のロジックを固定しておくと実務が楽になる。**

## 何を作り、何を作らないか

**法令が要求しているのは「書類を作ること」であって、システムを持つことではない。**
交付・承諾・受領・保管は人の操作で完結するため、**運用に委ねる**
（→ [docs/adr/0007](docs/adr/0007-document-preparation-only.md)）。

| | 担い手 |
| --- | --- |
| **法定記載事項を漏らさない契約書・重要事項説明書・変更契約書の作成** | **ツール** |
| **報酬の算定と業務報酬内訳書の作成** | **ツール** |
| 電磁的方法による交付の承諾、書面の交付、相手方からの受領 | **運用**（メールの定型文） |
| 重要事項の説明・免許証の提示 | **運用**（記録は重説書面の欄に残す） |
| 保管（電子帳簿保存法） | **運用**（Google Drive ＋事務処理規程） |

**持たないもの**: データベース、オブジェクトストレージ、発注者向け画面、決済、電子署名。

生成したPDFには**入力そのものを埋め込む**ので、開き直せば内容が完全に復元される。
**PDFが保存形式であり、変更契約は原契約のPDFから作る。**

## 実装（portal 側）

| | |
| --- | --- |
| ツール名（仮） | 設計等業務委託契約書 作成ツール（`contract-formatter`） |
| 雛形 | **Google ドキュメント**（プレースホルダー置換）。契約書・重要事項説明書・変更契約書・業務報酬内訳書 |
| 生成 | 雛形の複製 → 置換 → PDF書き出し → 入力を文書情報へ埋め込む |
| 保存 | **Google Drive**（新規作成／開く／保存／別名で保存） |
| 報酬算定 | **Rust → wasm**（`core/`）。画面とサーバが同じ実装を動かす |
| 認証 | **Clerk**（portal の既存の設定）。事務所スタッフのみ |

## いま決まっていないこと

**実装の着手を妨げるものは1つもない**（→ [docs/04-external-services.md §6](docs/04-external-services.md)）。

| | 内容 | 影響 |
| --- | --- | --- |
| **A** | **「相互に交付」をメール返信で構成できるか**（法22条の3の3第1項） | **最優先。** 否定されれば紙で2部を交わす運用に戻る。**作る書類は変わらない** |
| **B** | マネーフォワード クラウドBox が電帳法の要件を満たすか（未検証） | 満たせば保存の負担が下がる。**依存しない設計にしてある** |
| **C** | 業務報酬基準の告示の別表と算定式（原文未取得） | 報酬算定の実装に要る。**書類の作成には要らない** |
| **D** | 規則17条の39第1項1号のイ／ロの文言（原文未照合） | 交付の運用。どちらでも同じメールを送る |
| **E** | 改正法の施行期日政令と、施行に伴う政省令改正 | スケジュール。公布待ち |
